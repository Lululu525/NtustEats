## 變更內容
1. 封面改為「台灣科技大學 學生餐廳」，先選身分：**校內學生／教職員**、**其他校外人士**。
2. 校內登入輸入**學號／教職員編號**與**身分證字號**，比對成功才能登入，並自動帶出姓名與系級。
   例：B11201116／B000000000 → 陳庭瑜、工管系 大四。
3. 依學號規則解析身分：
   - 第 1 碼：學制（B 大學部、M 碩士、D 博士）
   - 第 2～4 碼：入學學年度（例 112）
   - 第 5～6 碼：系所代碼（01 工業管理系 … 54 先進半導體科技研究所，共 34 個）
   - 年級 = 目前學年度 − 入學學年度 + 1（8 月 1 日起算新學年）
4. 身分證字號檢查：1 個英文字母＋9 位數字，並驗證檢查碼。
5. 錯誤訊息逐項說明：學制碼錯、系所代碼不存在、身分證檢查碼錯、帳號與身分證不符。

## 建議新增／修改的需求（待審查）
- **FR-01（修改）**：校內師生以學號／教職員編號登入；系統依學號解析學制、入學學年、系所並顯示於個人頁。
- **FR-01a（新增）**：學號格式 `[BMD]` + 3 位入學學年 + 2 位系所代碼 + 3 位流水號；系所代碼須存在於系所代碼表。
- **BR-07（新增）**：系所代碼表（34 個代碼）。

## 需要審查決定的衝突 ⚠
- **與 C-3、NFR-07（個資最小化）衝突**：原規格只蒐集學號／手機、姓名、Email，**不包含身分證字號**。
  《個人資料保護法》要求蒐集須與目的相關且不逾越必要範圍；點餐系統以身分證字號驗證身分可能被認為逾越必要範圍。
- 原型的處理方式：身分證字號**只用於當下比對，不儲存**（不寫入 localStorage／sessionStorage），輸入欄位遮蔽顯示。
- **需求方說明（2026-11-10）**：系統最後會與**校務系統**連結；校務系統以「學號＋身分證字號」綁定學生身分，教職員亦同，因此登入需輸入身分證字號。
- 據此建議的處理：身分證字號**只轉送校務系統驗證、本系統不儲存**；C-3、NFR-07 修改為「身分證字號僅於登入時轉送校務系統驗證，不寫入本系統資料庫與日誌」，並新增 EI-4「校務系統身分驗證介面」。
- 決定：【組員／PO 填寫】
- **教職員編號格式**：校方未提供規則，原型暫用 `T` + 5 位數字，待確認。
